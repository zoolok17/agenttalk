## TL;DR

One real **security blocker** (path-traversal via agent names), four
**real improvements** worth shipping next, **six test-coverage gaps**
that should be filled before 0.3.0, and a clear runway of future
features. Recommended next release: a small **0.2.1 patch** for the
blocker + the two-line `--meta` exit-code fix, then a **0.3.0**

## Verified bugs

### 🚨 BLOCKER — Agent names allow filesystem path traversal

**Where:** `src/agenttalk/cli.py:123`, `src/agenttalk/store.py:86-89`,
`src/agenttalk/store.py:158-165`, `src/agenttalk/store.py:183-188`

**What's wrong:** `agenttalk init --agents X,Y` accepts any
comma-split string and the Store interpolates the names directly into
filesystem paths (`state/<agent>.cursor`, `state/<agent>.heartbeat`).
A name containing `..` or path separators escapes `.agenttalk/state/`.

**Codex's repro:**
```powershell
agenttalk init --agents 'alpha,..\..\outside'
# creates `outside.cursor` at the scratch project root,
# not under .agenttalk/state/
```

Duplicate names are also silently accepted (`--agents alpha,alpha`),
which then makes auto-peer derivation impossible and breaks
self-mail prevention.

**Fix:**
- Centralize agent-name validation. Restrict to a portable identifier
  pattern like `^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`, require
  uniqueness within the roster.
- Validate at three call sites: `init` (CLI), `load_config` (Store),
  `_resolve_self`/`_resolve_peer` (CLI helpers).
- Add tests for `..`, `/`, `\`, empty/whitespace, quotes, duplicates.
- Update README from "agent names are arbitrary strings" to "safe
  identifiers (alphanumeric + dot/underscore/dash)".

**Severity:** real blocker. Local-only attack (the user is the one
running `init`), but the README explicitly invites arbitrary names
and a future automated wrapper could pass untrusted input.

## Real improvements (not blockers, but ship soon)

### `--meta bad` exits 1 instead of 2

**Where:** `src/agenttalk/cli.py:46-50` (`_parse_meta` raises
`SystemExit("...")` which Python defaults to status 1).

**Why it matters:** exit 1 collides with `agenttalk wait`'s "timeout"
signal. If a skill body accidentally passes a malformed `--meta`,
the sk-loop would interpret the resulting exit 1 as a wait timeout
and loop. This is exactly the bug class we already fixed in the
identity resolvers (exit 2, not 1) — `_parse_meta` got missed.

**Fix:** raise `ValueError` and let `main()` convert to exit 2 via
the existing handler, or write to stderr + `sys.exit(2)` like the
identity resolvers do. Add a subprocess-style test.

### `init --force` retains old messages/cursors silently

**Where:** `src/agenttalk/store.py:75-90`.

**What's wrong:** `--force` overwrites `config.json` and emits a new
`session_id`, but leaves `messages/` and old `state/*.cursor` files
intact. The new session inherits everything from the old. `agenttalk
status` shows pre-`--force` message counts; transcripts include
prior-session data.

**Fix options:**
- **Conservative:** document `--force` precisely as "rewrite config
  only" and add `agenttalk reset` / `agenttalk new-session` for full
  cleanup with archive-or-delete semantics.
- **Aggressive:** make `--force` also clear `messages/`, `state/`,
  and (optionally) `sessions/` after confirming with the user.

I lean **conservative + new `reset` command** — `--force` is the kind
of flag users mash without reading docs, and surprise data loss is
worse than ambiguous flag semantics.

### `codex-config` writes invalid TOML for paths containing apostrophes

**Where:** `src/agenttalk/codex_config.py:49-50` (`_section_header`
always renders `[projects.'{project_dir}']`).

**What's wrong:** TOML literal strings (single-quoted) cannot contain
a single quote. A path like `D:\Code\Bob's Repo` writes a malformed
config block that breaks the user's whole Codex setup.

**Fix:** quote with a TOML-safe helper — use a basic string
(double-quoted with backslash escaping) when the path contains a
single quote, otherwise keep the literal form. Add tests for
apostrophe, double-quote, and backslash paths.

### `codex-config` writes non-atomically

**Where:** `src/agenttalk/codex_config.py:208,279,327` (direct
`write_text()` instead of temp-file + replace).

**What's wrong:** `Store._atomic_write_text` uses temp + `os.replace`
for safety. `codex_config` writes the user's global Codex config
directly. A crash, Ctrl-C, or concurrent edit can truncate or
half-write a user-level config that controls every Codex project.

**Fix:** factor `_atomic_write_text` from `store.py` into a shared
util (e.g. `agenttalk._atomic.write_text`) and use it from
`codex_config.py`. Two-line change with high leverage.

### No config schema validation on load

**Where:** `src/agenttalk/store.py:92-99`.

**What's wrong:** `load_config()` returns raw JSON. If
`.agenttalk/config.json` is malformed (wrong types, missing keys,
extra junk), the CLI gets cryptic tracebacks downstream rather than
a clean error pointing at the broken file.

**Fix:** validate at load time. Require `agents` to be a list of
unique safe names (gates the path-traversal blocker too). Reject
with exit 2 + remediation hint (`agenttalk init --force` or
`agenttalk reset`).

## Test coverage gaps

| Gap | Where | Why it matters |
|---|---|---|
| `cmd_end` has zero tests | `src/agenttalk/cli.py:347-365` | Sends goodbye + exports transcript. User-facing, has side effects. |
| `cmd_transcript` has zero tests | `src/agenttalk/cli.py:267-272` | The export command. |
| `cmd_wait` loop body untested | `src/agenttalk/cli.py:224-251` | We test the pre-loop exit-2 path, not the actual poll/timeout/message-received behavior. |
| `transcript.py` has no direct tests | `src/agenttalk/transcript.py` | `to_markdown` + `to_jsonl` invoked only indirectly. |
| `display.py` has no direct tests | `src/agenttalk/display.py` | Message renderer; Unicode + newlines + empty fields all untested. |
| No subprocess-style exit-code tests | — | We call `cli.main()` in-process; the actual `agenttalk` binary's exit codes aren't locked in. |
| No packaging/wheel tests | `pyproject.toml`, `dist/` | Nothing asserts the wheel ships all 10 skill files. A bad `[tool.hatch]` change could silently drop them. |
| No skill-body lint | `src/agenttalk/skills/*` | The skill bodies encode product logic (consult routing, no-auto-split, recursion guards). Drift will be silent. Currently only a few sentinel strings are checked. |

**Recommended:** before 0.3.0, hit at least the first six — they're
quick wins and they protect commands that users actually run.

## Doc / code mismatches

1. **README says agent names are "arbitrary strings"** — they aren't,
   once you account for the path-traversal blocker. Update wording.
2. **Exit codes not documented in the CLI reference table.** Users
   reading the README can't tell that `2` means usage error and `1`
   means timeout — a real distinction once you start scripting.
3. **PowerShell vs bash example asymmetry in skills.** Some show
   `uuidgen` fallback, others don't. Either standardize or document
   that the syntax varies by side.

---

## UX rough edges

1. **`agenttalk send` empty-body error** mentions `--allow-empty`
   awkwardly: *"use -m TEXT, --file PATH, pipe stdin, or
   --allow-empty"*. Re-word so the escape hatch is parenthetical:
   *"use -m TEXT, --file PATH, or pipe stdin (or pass --allow-empty
   to send an empty message)."*
2. **`agenttalk status` timeout / stale heuristic is hardcoded** to
   60 s in `cmd_status`. Consider a flag or config knob.
3. **Consult freshness check parses human-formatted status output.**
   Works for an LLM but brittle. See `status --json` below.

---

## Refactoring opportunities

1. **Factor `_atomic_write_text` out of `store.py`** into a shared
   util so `codex_config` (and future writers) can reuse it. Also
   doubles as the fix for the non-atomic codex_config write.
2. **Extract `cmd_wait`'s poll loop into a `wait_loop()` function**
   so it can be unit-tested without spawning subprocesses or calling
   `main()`. Currently the only way to test wait behavior is the
   blocking subprocess.
3. **Identity preambles are duplicated across 10 skill bodies.** A
   skill-body lint test would catch drift cheaply; full templating
   would be over-engineering for this scale.

## Future feature ideas (0.3.0+)

Roughly ordered by leverage-per-effort:

1. **`agenttalk status --json`** — structured output of root/session/
   messages/per-agent {cursor, unread, heartbeat, last_seen_seconds,
   stale}. High-value because the consult skill currently parses
   human text to check freshness. Also unlocks every external
   automation use case.
2. **`agenttalk doctor`** — single command that checks: is the store
   initialized? Are the bundled skills installed and current? Is the
   Codex config block present? Is the peer's heartbeat fresh? Is
   `agenttalk` on PATH for both sides? Cleanest UX win for new users.
3. **`agenttalk reset` / `agenttalk archive-session`** — explicit
   session lifecycle around old messages/cursors/transcripts. Lets
   us tighten the `--force` semantics safely.
4. **`agenttalk reply`** — reply to the last received message
   (matching its `request_id` automatically). Today the agent has to
   echo `request_id` manually; this would shorten consult / handoff
   skill bodies meaningfully.
5. **`agenttalk tail` / `agenttalk watch`** — human-mode message
   stream. Useful for a third terminal where you just watch both
   sides without acting as a listener.
6. **Message retention / prune** — `.agenttalk/messages/` grows
   unbounded today. A `prune --older-than 30d` or auto-prune-on-end
   would matter for long-lived projects.
7. **Optional message signatures (HMAC)** — for environments where
   the bus might be shared on a network-mounted dir.
8. **Live web dashboard** — local read-only HTTP server showing
   per-agent activity + transcript browser. Lower priority than the
   CLI primitives above.
9. **Multi-project view** — global `.agenttalk-sessions/` archive
   for browsing past transcripts across projects.

## Disputed / non-findings (for the record)

- **Explore claimed `--here` vs `--path` precedence was broken.**
  Verified by reading `cli.py:472-474`: the `--here` fill-in only
  triggers when `args.path` is unset. Explicit `--path X` wins.
  Behavior is correct.
- **Explore noted the empty-cursor-vs-string-comparison in
  `messages_for`.** Lexicographic `m.id > ""` correctly returns all
  messages on first wait. Intended behavior; only the documentation
  could be slightly clearer.
