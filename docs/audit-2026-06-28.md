# Fresh independent audit — 2026-06-28 (@ master 97fa3a1 / v0.38.0)

Point-in-time historical record. The **living** tracker (current status of each
fix) is `docs/ISSUES.md`; the architecture rationale is `docs/DESIGN.md`. This
document preserves the methodology, the per-reviewer findings, and what the
reviewers probed and found solid.

## Why & method

The operator asked every team member to spawn its **own independent fresh
reviewer** (un-primed by our build decisions) and pool the results — a
multi-perspective adversarial pass over the whole codebase. Six fresh agents ran:

| Reviewer | Lens |
|---|---|
| claude-security | security + concurrency / atomicity |
| claude-correctness | correctness + CLI/doc contract-drift + edge cases |
| claude-test-coverage | coverage gaps + regression-test proposal |
| dev-2 fresh agent | full-scope, dev-2 triage |
| reviewer-1 fresh agent ("Hubble") | full-scope; reviewer-1 reproduced #1 |
| codex fresh agent ("Kepler") | full-scope; codex reconciled to source |

Method: each agent read the source directly; the lead then **verified every
finding against the code, deduped, and killed false positives** before this
record. Convergence (multiple independent reviewers on the same defect) is noted
because it raises confidence sharply.

Outcome headline: the audit found a cluster of **real, shipped false-GO /
authority defects the normal review cadence had missed** — validating the
assurance posture (the arc exists precisely to catch this class). None were
remotely exploitable or recall-worthy; all are flowing into v0.40.0 / v0.40.1
with regression tests that pin them.

## Findings by theme

### Theme 1 — `gates.py`: four fail-opens + zero dedicated tests (the #1 target)
The subsystem meant to *prevent* false-GO releases was the weakest link. Each let
a release report **GO** when it should HOLD:

1. **Corrupt-file overwrite false-GO** *(claude-security; lead-verified)* —
   `set_gate`/`waive_gate` ignore `load_error`, so any unrelated `gate set`
   silently rewrites a corrupt `gates.json`, dropping the corruption HOLD and all
   prior gates. Trigger: pre-existing corruption/tamper.
2. **Unlocked read-modify-write** *(claude-security + reviewer-1 + dev-2 — 3
   reviewers)* — gate mutations lack `_config_lock`; concurrent writers clobber a
   recorded blocker.
3. **Scoped-drop absence=pass** *(dev-2)* — a required gate recorded under a
   mismatched scope passes the missing-check *and* is filtered out → never blocks.
4. **`skipped` blocker → GO** *(reviewer-1, reproduced via CLI on master)* —
   `gate set status=skipped severity=blocker required` returns GO with empty
   blockers; `_gate_verdict` only blocked blockers on red/unknown.

Plus **no `tests/test_gates.py`** at all *(claude-test-coverage, P0 coverage)* —
the buggiest critical module was also the least-tested. → all C1 / v0.40.0.

### Theme 2 — lane shared-path approval over-grant (3 reviewers)
*(dev-2 + claude-test-coverage + reviewer-1)*
- `_shared_approved` accepted a path **prefix** match, so a broad `schema/**`
  approval cleared a nested `schema/secret.sql` whose distinct approvers were
  never consulted.
- The verdict never **revalidated** persisted approvals (approver/authority/
  epoch/registry hash) — a forged/corrupt `lanes.json` approval cleared the HOLD.
- The documented `HOLD_SHARED_WRONG_APPROVAL` code was **declared but never
  emitted** (dead code masking the gap).
- **Overlapping-glob residual** *(reviewer-1, reproduced — escalated to a 0.40.0
  blocker)*: even after binding an approval to one entry, a broad `shared/**`
  approval still cleared a more-specific sibling entry. Fix requires
  **most-specific-matching-entry-wins**, ties failing closed via a new
  `HOLD_SHARED_AMBIGUOUS_ENTRY` (decision D-11). → C2 / v0.40.0.

### Theme 3 — wrapper loop-exit & one-shot reviewer
- **`kind=end` from any sender** *(dev-2)* — already **fixed in v0.39.0**; the
  audit independently re-derived exactly what stand-down closed.
- **Release-authority drift** *(codex/Kepler)* — `is_release_authorized` carried a
  zero-lead fallback diverging from the v0.39 fail-closed envelope → unify on the
  single resolver. → C3 / v0.40.0.
- **One-shot reviewer starves/hangs** behind an unrelated unread message
  *(dev-2 + reviewer-1)* + leaves a stale `.waiting` marker on exit *(Kepler)* →
  scoped receive + bounded timeout + `try/finally clear_waiting`. → C3 / v0.40.0.

### Theme 4 — knowledge (v0.38.0, conservative gaps)
- `roster --expertise` credits the **latest** view, not the curated set — a later
  uncurated publish drops a verified author's credit *(claude-correctness, P2)*.
- `wp`/`request`/null-`verified_against_sha` anchors fail **open** on staleness
  *(reviewer-1 + claude-correctness + Kepler)*.
- Publish vs curate use **different** append code with no fsync — a crash can drop
  the latest *(Kepler, P2)*.
- `onboard` help/README overstate ("bounded digest grouped by domain/type")
  *(claude-correctness, P3)*. → C4 / v0.40.1.

### Theme 5 — TOCTOUs (P2)
- `close publish` unlocked → can double-fire the release barrier (no false-GO;
  verdict re-derived) *(claude-security)*.
- `lane deliver` clears the lane on the sandbox direct-write path without reading
  the artifact back *(dev-2)*.
- `clear_restart_request` read+unlink unguarded *(dev-2)*. → C5 / v0.40.1.

### Theme 6 — defense-in-depth nits (P3, banked)
State helpers don't re-`validate_agent_name` (CLI validates upstream);
`_process_alive` treats exit 259 (STILL_ACTIVE) as alive; `domains` normalize
allows trailing dots / reserved device names (not a path escape); ephemeral
`skill`/`profile` weak validation (not shell-exploitable; layered behind
disabled-by-default + authorized-lead).

## What was probed and found SOLID (no defect)
Reported because "we tried to break X and couldn't" is itself evidence:
- **Knowledge curate-gate / forged-`verified` siblings** — the event-kind ↔
  authority-state matrix holds; a publish can't self-declare `verified`; the
  curated set stays separate from open capture.
- **Path traversal** in anchors/globs — `normalize_repo_path` rejects NUL /
  absolute / drive-relative / UNC / `..`-escape; crafted `**/../x` normalizes
  within-repo; git args are always fixed argv, never shell.
- **Untrusted body as control flow** — only loop-control keys on `kind` +
  authenticated `from`; prose can't drive a loop exit or state change.
- **Atomic writes** — temp + fsync + `os.replace`, sandbox-direct latched
  correctly; cursor biases to re-delivery.
- **Authority resolvers** (post-v0.39) and **lane deliver** fingerprint-recheck-
  under-lock + artifact-before-clear.
- **CLI contract drift** — an exhaustive sweep (~600 arg accesses, all `choices`,
  all flag spellings, exit codes) found **zero** drift; the `release --reason`
  class is fully eliminated.

## Regression test (operator request)
The coverage reviewer proposed, and the batch builds, `tests/test_e2e_lifecycle.py`:
an **in-process `cli.main`** narrative over a **real throwaway git repo**
(pinned author/committer dates, `shutil.which("git")` skip-guard), asserting
**exit codes** (the GO=0/HOLD=3/usage=2 contract supervisors depend on) + JSON
verdict shape + on-disk state across init → send/reply → broadcast → domains →
lane → gate/close → knowledge → **reset** — including **negative assertions that
the C1/C2/C3 bugs stay fixed** and that `reset` preserves the durable set. It
covers the previously-untested CLI↔core wiring, the impure git adapter, and the
reset durability boundary.
