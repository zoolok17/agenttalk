### PR 98: nineteen rounds, and what convergence actually looked like

Findings by round: 17 → 6 → 2 → 4 → 1 → 3 → 2 → 2 → 3 → 2 → 1 → 2 → 2 → 1. Green CI was wrong on this
PR every single time it was green.

The useful signal was never the count, it was the **character** of the findings:
- Rounds 9-10 were self-inflicted — fixes right at the named site, blast radius unsurveyed. I made a
  standing requirement that every fix name its sibling call sites with a keep-or-skip reason.
- That worked, and then round 12 exposed a flaw in my own rule: I had accepted "the suppress fix is
  purely additive, no newly-covered set to check". **A `suppress` is not additive** — it creates a new
  reachable path where execution continues past a failure that previously aborted. Downstream must be
  safe in the state the suppressed failure leaves behind. It wasn't: an unbounded `communicate()`
  became reachable after a failed kill.
- Round 16 refined it again: dev-6 *did* check the inverse, but only the nearest neighbouring case. It
  missed the **different domain** — launches that are not Python at all, where a module boundary is a
  meaningless question. The guard it removed was invisibly also keeping non-Python launches out; our
  own generated manual archetype started failing our own validator.
- Rounds 18-19 were the same terminal-token class one layer up each time: first CPython's own
  grammar (`-V`, `-h`, `-m`, `-c`, bare `-`), then agenttalk's own argparse (`wrap --help` and
  parse-invalid tails exit before streams install while Launch still commits a generation).

**The fix that ended the field-loss class was structural.** After three rounds of `module_args_from`
being dropped at each site that rebuilt a config, dev-6 found there is exactly ONE hand-built
`cfg_agent` in the tree and made it store the launch dict **wholesale** — so every later lifecycle
function preserves it for free and a *future* field survives without anyone enumerating anything.
That is the difference between fixing the fourth instance and making a fifth impossible.

Two habits from dev-6 worth keeping as standard: it **producer-checked its own tests** and found one
asserting the bug as passing behaviour, then updated it rather than leaving a green test certifying
wrong behaviour; and it **rejected two designs with reasons** before landing on a third, including
catching that restoring `sys.excepthook` in a `finally` means the hook can never fire, since `finally`
runs while the exception is still unwinding.

**Three universal claims, three failures on unenumerated paths.** That is a methodological result, not
three unrelated bugs: enumeration is the wrong instrument for this property. Authorized a structural
redesign instead — the exact-executor capability becomes a required operand to CONSTRUCT any

Same move as the launch-dict fix. dev-4 recommended it over the easier narrowed claim, scoped it at
350-500 lines (much of which DELETES the 17-entry inventory), and withdrew its own whole-state
byte-identical promise to get there.

Two permanent capability reductions now exist and must be stated together where an operator reads
them: POSIX named teardown, and automatic quarantine retirement. An operator who discovers the second
during an incident will not care that it was technically documented.

### The dogfood asymmetry (operator's observation, worth recording)

`supervisor.ps1:471` prepends `<root>/src` to PYTHONPATH when it detects a source checkout, so THIS
host's supervisor and wrappers run the working tree. Merging #120 changed nine live agents' supervisor
decisions within two hours, with no install and no restart. My first framing — "master is production,
file it as a defect" — was **wrong**, and the operator corrected it: every real user installs the
package and never takes that branch. Verified: `owned_process_tree_v2` is absent from v0.80.0, so no
released version ever wrote that schema and no installed user can hit the resulting warnings.

The sharper consequence is the inverse: **we continuously validate the one configuration nobody
ships, and get no signal about the shipped artifact.** Recorded on **#68** as a hard requirement — the
fleet simulator must run a built-and-installed wheel, not import `src`, or it reproduces the blind
spot at higher fidelity instead of closing it. First scenario: install release N, run a stub fleet
until it writes real state, upgrade in place to N+1, assert nothing the new validator refuses to read.
