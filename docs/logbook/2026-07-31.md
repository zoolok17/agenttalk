## The fleet-wide CI red was the lead's own commit

For several cycles the lead reported "four independent flakes" across four unrelated branches. It was one
blocker, and the lead had introduced it.

Publishing dev-4's 87-A fold (`0ae2e88`) added a `ChildEstablishmentGuardV1.key` schema type — a string
added to satisfy panel blocker B1 — and gitleaks' `generic-api-key` rule matched it. Because
`actions/checkout` runs with `fetch-depth: 0`, **every PR run scans all fetched branches**, so a commit on
a *design* branch reddened `linux/3.12` on every unrelated PR. Master's green predated the push, which is
why the contradiction looked unresolvable.

The discriminating evidence was available early — two unrelated PRs failing on the identical lane with an
identical leak count of 2 — and the lead held it while calling them independent. dev-8 fixed it correctly:
three `.gitleaksignore` entries pinned to commit + file + rule + **line**, with a comment justifying each.
Not a rule disable, not a path glob. False positives, and a broader fix would have been refused.

## One principle, three faces

Three separate defects today were the same mistake — an acknowledgement mistaken for an outcome:

- a **reported kill** is not an exit confirmation (connector on PR 101; dev-7 fixed)
- a **successful cancel submission** is not a cancellation (`gh run cancel` accepted four requests that
  took 30–70 minutes to apply; the lead read the ✓ as done)
- a **polled `None`** is not an exit confirmation (PR 98: `on_exit` emitted `child_exited` with a null
  return code while the process could still be alive)

Reading *state* rather than *messages* was the single most reliable habit of the day, and every place the
lead skipped it produced a wrong report.

## #117's own purpose was nearly defeated

#117 captures wrapper stdout/stderr so a dying wrapper's traceback is not destroyed by construction. The
connector found that `cmd_wrap`'s `finally` restored the raw streams **before** Python emits an uncaught
traceback — so with a full first segment, that traceback bypassed the bounded tee and was omitted from the
rotating tail. The feature would have captured everything except the one line anyone wants. Fixed by
printing inside the except block while the tee is still installed, guarded so a signal-driven intentional
exit gets no spurious dump.

Also fixed there: generation pruning sorted by wall-clock directory name, so a backward clock correction
made stale future-dated generations look permanently newest and the genuinely newest got evicted. Replaced
with a monotonic per-agent launch sequence. Same lesson as the UTC-clock keystone fix — wall clock is not
an ordering key on a machine an operator can adjust.

## The review-tooling experiment, scored against a real baseline

The operator asked why the automated reviewer could not be replicated in-house. Two corrections came out of it:
the reviewer is **not free** (it draws on the same Codex budget as our own workers, so it competes with them),
and the 2000-minute Actions allowance **does not bind** because this repo is public — today's burn alone would
have exceeded it many times over. The scarce resource is provider tokens, not CI minutes.

The bigger finding: **agenttalk already ships this.** `agenttalk request-launch --profile --skill --revision
--base-revision --path` queues an evidence-only ephemeral adversarial review, frozen to a full SHA, with a
fresh session and identity retired after one typed result. `ephemeral_reviewers` is `enabled:false` and
unconfigured, so it has never been used. The design already encodes lessons relearned by hand this week:
`approved` is evidence only and never a counted signoff; `needs-info`/`malformed`/no-result all fall to HOLD.

Scored two cold Claude reviewers against seven connector findings that implementers had independently
confirmed in code:

| diff | connector | cold Claude | overlap |
|---|---|---|---|
| `a51639d..13e1697` | 4 confirmed | 1 | 0 |
| `a51639d..ee177af` | 3 confirmed | 2 | 1, and more complete |

On the one shared finding the cold reviewer also named the *second* site, which the connector only found a
round later. Three new candidate defects surfaced that the connector missed, two verified real by reading the
code — including a fallback that hands a wrapper logging capability without redirection, silencing its visible
console after 256 KiB while it still reads healthy.

Verdict: **diversity, not replacement.** Run both, merge findings. And one methodological lesson that is the
lead's own: the brief demanded a constructible failure scenario and told reviewers to *drop* anything they
could not construct. Both did — one explicitly dropped the very area a connector finding covered. That traded
recall for precision, which is backwards for a merge gate. Report low-confidence, adjudicate later.

### Lead lessons from this session, in priority order

1. **Read tool output before counting it.** Every wrong claim in the last two hours traced to piping a
   command through `grep -c` and treating the filtered result as the tool's answer. `agenttalk drain`
   was printing *"refusing an unbounded consuming read on a pipe; pass --limit N"* in plain English and
   I read it as an empty inbox — then invented a read-path defect, chased three wrong hypotheses, and
   **told the operator a healthy agent had parked.** Bounded reads, unpiped, and read the words.
2. **The lead's own instrument needs the same discipline the lead imposes.** All day I required workers to
   set `CWD` *and* `PYTHONPATH` on every call, and exempted my own commands because they were "just reads".
   Note also: the installed `agenttalk` is `0.79.1` while source is `0.80.0`. Not the cause of anything
   here, but a live skew — prefer `PYTHONPATH=<repo>/src`.
3. **Compact after a release ships.** v0.80.0 shipped at 11:48Z. That was the natural boundary; the session
   ran seven hours past it and the degradation was measurable. Do not rely on noticing — use the trigger.
4. **Sorting findings by area beats counting them.** PR 98 looked divergent at 17 findings until they were
   grouped: five areas, each repeating the previous fix. That table is what justified demanding invariants
   instead of a sixth fold, and it worked.
5. **Close reviewer threads with an outcome, same day.** Two threads were left owed for hours this session
   after the lesson had already been learned once. `owed-inbound` in `agenttalk threads` is the check.
